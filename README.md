# qPioneer: All-in-One qPCR Analysis App

**qPioneer** is a Streamlit application for interactive analysis of qPCR data on 96- and 384-well plates.
Try it online: **https://qpioneer.kachkin.pro** (no sign-up; there is a built-in example).

* **Data upload & annotation:** TXT/CSV/XLSX; assign genes, conditions and replicates on a visual plate layout.
* **Quality control:** σ-based outlier detection, outlier and pass rates.
* **Normalization & expression:** ΔCt against the reference gene and relative expression 2⁻ΔCt.
* **Statistics:** pairwise t-tests per gene with Bonferroni correction.
* **Interactive plots:** boxplots and barplots with raw data points and significance brackets.
* **Export:** CSV, JSON, Excel, PNG; full report in PDF and HTML.
* **Sessions as files:** save the whole session or the plate annotation as JSON and continue later.
* **Interface:** Russian (default) and English.

---

## 🔒 Public mode (default)

Without Streamlit secrets the app runs in public mode:

* no login and no cloud storage;
* uploaded files are processed in memory and are not written to disk;
* sessions, annotations, results and reports are downloaded as files — the data stays with the user.

This is how https://qpioneer.kachkin.pro runs.

---

## 🚀 Features

1. **Data Upload**: TXT/CSV/XLSX files with configurable delimiter, header rows and column names
   (`Pos` for well position, `Cp` for Ct values by default). Upload limit in Docker — 20 MB.
2. **Example data**: the **Load example** button loads a synthetic 96-well plate (ACTB as reference gene,
   SOX2 and PAX6, Control and Treated, 3 replicates each) with a ready annotation. The files are in `examples/`
   and are generated by `examples/make_demo.py`. The data are invented, not experimental results.
3. **Plate Annotation**, two steps:
   * **Step 1:** mark wells for genes (`reference gene`, `target gene`, `negative control`).
   * **Step 2:** mark wells for conditions and replicates.
4. **QC & Analysis**: outliers by standard deviation threshold, QC summary, ΔCt and 2⁻ΔCt.
5. **Statistics & Visualization**: t-tests with Bonferroni correction, Plotly boxplots and barplots,
   PNG download of every chart.
6. **Session & Annotation files**: save/restore the entire session (data, annotation, results) or only the
   annotation as JSON.
7. **Full Report**: PDF and HTML with QC, the expression table and plots. The PDF embeds DejaVu fonts (`fonts/`),
   so gene and condition names in Cyrillic and other scripts work.

## 🔧 Installation

```bash
git clone https://github.com/puerhmaster/qPioneer.git
cd qPioneer
python3 -m venv venv
source venv/bin/activate    # Linux / macOS
venv\Scripts\activate       # Windows
pip install --upgrade pip
pip install -r requirements.txt
```

Python 3.12 is recommended (dependencies are pinned in `requirements.txt`).

## ▶️ Usage

```bash
streamlit run qpcr_analyse_app.py
```

or in Docker (settings — `.streamlit/config.toml`: headless, XSRF protection, 20 MB upload limit,
no usage statistics; the container runs as a non-root user):

```bash
docker build -t qpioneer .
docker run --rm -p 127.0.0.1:8501:8501 qpioneer
```

Workflow:

1. Upload a qPCR file or click **Load example**.
2. Adjust the file format in the sidebar if needed.
3. Annotate wells on the **Genes** and **Condition & Replicates** tabs.
4. Set the outlier threshold and click **Calculate expression**.
5. Review QC and plots, download results and the full report.
6. Save the session to a file to continue later.

## ☁️ Optional: shared cloud saving (private deployments only)

The code can also save sessions, annotations and reports to a GitHub repository. It is **off** unless a
`[github]` section is present in Streamlit secrets (`.streamlit/secrets.toml` next to the app, or
`/app/.streamlit/secrets.toml` in Docker):

```toml
[github]
token     = "<GitHub token with access to repo_name>"
repo_name = "<owner>/qPioneer-user-data"
```

> ⚠️ This is **one shared token**, not a per-user login. Every user of the deployment writes to and reads from
> the same folder (named after the token owner), so everyone sees everyone's files. Enable it only for a private
> deployment used by one person or one trusted team — never on a public address.

There is no GitHub or Google sign-in in the app; other secrets sections are ignored.
